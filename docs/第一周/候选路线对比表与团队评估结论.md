# 候选技术路线方案对比
## 项目：企业职工人事在线管理信息系统
> 编写日期：2026-09-10

---

## 一、方案概览

| 维度 | 方案 A：Spring Boot 全家桶 | 方案 B：SSM 传统组合 | 方案 C：Django + Vue |
|------|---------------------------|---------------------|---------------------|
| 简述 | Spring Boot + Spring MVC + MyBatis + Vue + MySQL 8.0 | Spring + Spring MVC + MyBatis + JSP + MySQL 8.0 | Django + DRF + Vue + MySQL 8.0 |
| 后端语言 | Java | Java | Python |

---

## 二、方案 A：Spring Boot 全家桶

### 2.1 技术栈组成

| 层 | 技术 | 版本建议 |
|----|------|----------|
| 表现层 | Vue 3 + Element Plus / Thymeleaf 模板 | Vue 3.4+ |
| 后端框架 | Spring Boot | 2.7.x 或 3.2.x |
| Web 层 | Spring MVC | 由 Spring Boot 集成 |
| ORM | MyBatis + MyBatis-Plus | MyBatis 3.5+ |
| 安全 | Spring Security + JWT / Session | Spring Security 5.7+ |
| 数据库 | MySQL | 8.0 |
| 连接池 | Druid | 1.2+ |
| 反向代理 | Nginx + Tomcat 内嵌 | Nginx 1.20+ / Tomcat 9/10 |
| JDK | JDK | 11 或 17 |
| 构建工具 | Maven | 3.8+ |

### 2.2 优势
1. Spring Boot 约定优于配置，开箱即用，搭建快、启动快，毕设开发效率高。
2. MyBatis-Plus 提供强大的 CRUD 封装 + 分页插件 + 字段自动填充，节省 SQL 编写成本。
3. Spring Security 天然支持 RBAC + 方法级注解权限控制（@PreAuthorize），非常契合"三类角色 + 本人数据隔离"需求。
4. 生态丰富，社区资料多，毕设答辩时被广泛认可为"主流企业级方案"。

### 2.3 劣势
1. 对比其他方案略显"重"，需要理解 Spring 全家桶。
2. 前端若使用 Vue，需要前后端分离联调，会增加一定工作量。

### 2.4 适用场景
- 后续扩展为真实企业内部系统
- 团队熟悉 Java 生态

---

## 三、方案 B：SSM 传统组合

### 3.1 技术栈组成

| 层 | 技术 | 版本建议 |
|----|------|----------|
| 表现层 | JSP + JSTL + Bootstrap / LayUI | JSP 2.3 |
| 后端框架 | Spring | 5.3.x |
| Web 层 | Spring MVC | 5.3.x |
| ORM | MyBatis | 3.5+ |
| 安全 | Shiro / Spring Security | Shiro 1.10+ |
| 数据库 | MySQL | 8.0 |
| 服务器 | Tomcat | 9.0+ |
| JDK | JDK | 8 或 11 |
| 构建工具 | Maven | 3.6+ |

### 3.2 优势
1. 技术成熟、教学场景经典，是大量 Java Web 教材的默认栈。
2. JSP 前后端不分离，开发简单，单人即可完成。
3. 部署简单：打成 war 包丢到 Tomcat 即可。

### 3.3 劣势
1. 大量 XML 配置，搭建环境耗时，开发效率低于 Spring Boot。
2. JSP 技术已逐步被淘汰，答辩时略显"过时"。

### 3.4 适用场景
- 学校教学要求"必须使用 SSM"
- 团队对 Spring Boot 不熟悉但熟悉 SSM

## 四、方案 C：Django + Vue（Python 路线）

### 4.1 技术栈组成

| 层 | 技术 | 版本建议 |
|----|------|----------|
| 表现层 | Vue 3 + Element Plus | Vue 3.4+ |
| 后端框架 | Django | 4.2 LTS / 5.x |
| API 层 | Django REST Framework | 3.14+ |
| 安全 | DRF Token / JWT (djangorestframework-simplejwt) | — |
| 数据库 | MySQL | 8.0 |
| 服务器 | Nginx + Gunicorn | — |
| 语言 | Python | 3.10+ |

### 4.2 优势
1. Django 自带 Admin 后台、ORM、权限系统，开发效率极高。
2. 适合快速搭建 CRUD 类管理信息系统。
3. Python 语法简洁，对零基础转行者更友好。

### 4.3 劣势
1. 与毕设主流技术栈（Java）差异较大，答辩时若指导教师倾向 Java，可能不被认可。
2. DRF 实现"行级数据隔离"需要借助自定义过滤器 / Queryset，调试成本反而高于 Spring Security。

### 4.4 适用场景
- 团队主语言为 Python
- 学校对技术栈没有强制要求

## 六、团队评估结论

**结论：团队一致同意采用方案 A（Spring Boot 全家桶）。**

说实话，最后我们几个坐下来讨论的时候，三个方案摆在一起看，其实差距没那么夸张，但综合下来还是 A 最稳。以下是大家开会时聊出来的几点真实想法：

### 6.1 关于方案 B（SSM 传统组合）

老王一开始是倾向 SSM 的，毕竟他之前做过的项目都是这套，搭起来闭着眼都行。但我跟他说了，**SSM 那一堆 XML 配置光是搭环境就得折腾一两天**，我们这次就三个人、时间又紧，没必要把精力耗在配置上。而且答辩的时候，评委老师一看到 JSP 心里就默认你"老一套"，没什么加分项。老王听完也就没再坚持。

### 6.2 关于方案 C（Django + Vue）

小李是 Python 党，他挺想试一下 Django 的，毕竟 Admin 后台是真心方便。但我俩都担心一个事——**答辩时指导老师大概率会问 Java 相关的东西**，Django 那套 ORM 跟 MyBatis 思路差太多，万一被问到"你这个 RBAC 怎么实现的"，用 Django 反而不好讲清楚底层。最后小李自己也认了，说"Django 是快，但讲不清楚对我们更亏"。

### 6.3 为什么最终选 A

主要有三个原因，说出来都比较实在：

1. **我们三个人都更熟Java和 Spring Boot。** 平均下来 A 的学习成本最低，分工也好安排。
2. **本次需求里"三类角色 + 本人数据隔离"是核心痛点。** Spring Security 的 `@PreAuthorize` + 自定义注解基本就是为这个场景设计的，写起来很自然；用 SSM 得自己写拦截器+注解解析，啰嗦；用 Django 反而要绕一圈。
。

### 6.4 不是没有顾虑

也不是说 A 完美。**最担心的点其实就两个**：
- 前后端分离之后联调会比较烦，跨域、JWT、接口约定这些都得提前统一好；
- Spring Security 那一套权限链，新手第一次配很容易踩坑，配置文件写错一个地方整条链就断。

但这些都算是"能解决的麻烦"，不像 SSM 的 XML 是"必须忍受的麻烦"。

> 最终方案：方案 A — Spring Boot + MyBatis-Plus + Vue 3 + Element Plus + MySQL 8.0。
> 评审日期：2026-09-10，团队全员一致通过。
