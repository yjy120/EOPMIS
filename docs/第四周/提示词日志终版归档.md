## 项目背景设定
> **Prompt 1**：你是需求/提示工程师，我们完成 PRD 文档。
> **项目题目**：企业职工人事在线管理信息系统的设计与实现
> **用户角色**：
> 1. 系统管理员：最高权限，管理系统账号，分配角色权限，不负责人事业务。
> 2. 人事专员：业务操作人员，维护部门、岗位、职工档案、劳动合同、人事调动，可以维护薪资、考勤相关记录。

> 3. 只输出以上内容，不要写功能性需求、用例、系统边界、附录；完成后等待我确认，我回复你之后再进行下一步。

### 协作要点（可复用经验）
1. **分章节迭代**：每轮只输出一到两个章节，便于人工评审与回退修改。
2. **硬性约束前置**：用户每次都明确给出"硬性要求"清单（如数量、字段、范围），AI 必须严格遵守。
3. **角色与权限边界清晰**：三类角色（系统管理员 / 人事专员 / 普通职工）及其权限隔离贯穿全文，是本项目最核心的约束。
4. **范围控制**：通过"系统边界"明确本期不实现的内容（薪资自动核算、复杂考勤、审批流等），避免范围蔓延。
5. **变更追溯**：附录中通过"需求变更记录表"记录 15 条变更，体现迭代过程。
6. **最终交付形式**：用户最后要求将全文输出为 `.md` 文件，体现"可直接交付"的工程化意识。

1. **提示词工程三要素贯穿全程**：角色设定清晰（需求工程师→设计→开发）、依据文档显式声明（文档链逐级传递）、硬性约束前置（数量/字段/范围写明）。
2. **"AI 初稿 + 人工评审定稿"闭环**：每阶段 AI 产出 → 小组评审 → 人工修订 → 作为下一阶段输入，遗留问题显式移交（M09 请假审批贯穿 PRD → 架构 → 详细设计 → 待办清单）。
3. **环境类问题占比最高**：字符集双重编码（CONVERT(BINARY ...) 修复）、双 MySQL 实例（IPv4 MariaDB / IPv6 MySQL 8.0）、JDK 版本兼容、PowerShell 语法差异、localStorage 权限缓存——环境排查要用证据（端口、版本号、hex）说话，不猜。
4. **权限一致性需要单一真源**：种子账号/菜单绑定在 DataInitRunner、schema-rebuild.sql 与运行库三处必须同步；admin 误绑与 HR 漏绑两次事故均源于此。
5. **范围隔离纪律**：每周开发都声明"只改本用例相关文件，不影响已完成用例"，并以冒烟测试回归验证，保证功能持续可演示。

7. **文档与代码一致性**：模型改名/类迁移后必须全局搜索旧引用（SysPermission 残留教训）；归档文档中的相对链接随位置迁移需同步修正。
