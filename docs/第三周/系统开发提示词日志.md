## 轮次 3：中文乱码修复

**用户原话**：
> 可是我现在人事专员的那个页面里面。只有部门管理和岗位管理这两个按钮，但是它点不进去啊，里面的什么内容都没有啊，我甚至点不进去。所以说你放在那就是个摆设让我看吗？

**问题诊断**：
- 不是"点不进去"也不是"空白"——是中文乱码（看起来像空白）
- sys_dept 表存在**双重 UTF-8 编码**：MySQL 服务端 latin1 默认 + PowerShell 导入时 UTF-8 字节被当 GBK 处理，导致"总公司"实际存的是双重编码字节
- sys_position 新建数据被替换为 `?`（JDBC URL 的 `sessionVariables` 配置未生效）
- deptName 字段读取仍乱码（Druid `connection-init-sqls` 配置未生效）
- 由于没有管理员权限，`net stop/start MySQL80` 无法执行（Access denied）

**AI 响应摘要**：
1. **数据层修复**：执行 SQL
   ```sql
   UPDATE sys_dept SET name = CONVERT(BINARY CONVERT(name USING latin1) USING utf8mb4),
                       leader = CONVERT(BINARY CONVERT(leader USING latin1) USING utf8mb4);
   ```
   用 `BINARY` 强制重新解释字节，恢复成正确的 UTF-8（hex `E680BB E585AC E58FB8` = "总公司"）
2. **应用层修复**：新增 [DruidCharsetConfig.java](../backend/src/main/java/com/eopmis/config/DruidCharsetConfig.java)，在 Spring 启动后主动调用 `DruidDataSource.setConnectionInitSqls(["SET NAMES utf8mb4"])` 并实际跑一次 SET NAMES 验证
3. **清理乱码数据**：删除 sys_position 表里 id=2 的 `?????` 测试数据
4. **验证**：
   - 数据库 hex 已确认是正确 UTF-8 字节
   - 浏览器实测：部门管理显示"总公司、研发中心、人力资源部、财务部、后端组、前端组"，岗位管理显示"高级工程师测试"

**用户原话**：

- **后端权限变更后，前端必须清 localStorage + 重新登录才能生效**
