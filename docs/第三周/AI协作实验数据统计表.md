## 0. 度量说明

本文档量化"AI 辅助开发"在该项目中的实际效果。所有数据按以下口径统计：
| 指标 | 定义 | 数据来源 |
|------|------|----------|
| **代码总行数** | 项目内 `.java` / `.vue` / `.js` 文件的有效行（去空行 + 去注释） | 实测 grep |
| **AI 生成代码占比** | AI 直接输出的代码行数 / 代码总行数 | 基于 [系统开发提示词日志](系统开发提示词日志.md) 推算 |
| **人工修改率** | 人工（用户）后续修改的行数 / 代码总行数 | 基于 [缺陷跟踪表](缺陷跟踪表.md) + 用户反馈轮次推算 |
| **修复轮次** | 每个缺陷从发现到闭环所需的 AI 响应轮数 | 基于 [缺陷跟踪表](缺陷跟踪表.md) + [每日迭代日志](每日迭代日志.md) |
| **人机耗时** | AI 累计响应时间 vs 人工累计反馈时间 vs 等效传统开发时间 | 基于会话日志估算 |
**重要前提**：AI 与人工协作无明显分界点（中间产物可能反复"AI 输出 → 人工微调 → AI 重构"），下文采用"按贡献行数归属主导方"的原则近似统计。

## 2. AI 生成代码占比
### 2.1 总体占比

| 项 | 行数 | 占比 |
|----|------|------|
| **代码总行数** | **8,592** | 100% |
| AI 直接生成 | 8,058 | **93.8%** |
| 人工直接编写 | 130 | 1.5% |
| 人工后续修改 | 404 | 4.7% |

> **AI 生成占比 93.8%**：项目代码几乎全部由 AI 在多轮对话中产出；人工直接键入的代码量极少（仅个别 key/voucher/数据库迁移脚本等）。
### 2.2 分阶段 AI 占比

| 阶段 | AI 占比 | 说明 |
|------|---------|------|
| 第一周（PRD 编制） | 60% | PRD 由用户主导撰写，AI 仅做格式润色、目录生成、章节补全 |
| 第二周（设计文档） | 85% | 概要/详细/数据库设计文档由 AI 起草，用户做审阅批注 |
| 第二周末（原型代码） | 98% | Spring Boot 基础骨架（97 个 Java 文件中前 30 个）几乎全部 AI 一次性产出 |
| 第三周 UC-001~017 编码 | 95% | 每次任务"用户提需求 → AI 一次性产出 5~15 个文件"为标准节奏 |
| 第三周文档（迭代日志/缺陷表/执行记录） | 95% | AI 基于会话内容回填，**人工未改动** |
### 2.3 分文件类型 AI 占比

| 文件类型 | AI 占比 | 备注 |
|----------|---------|------|
| Entity / DTO | 99% | 字段映射固定模板，AI 命中率最高 |
| Mapper XML | 92% | CRUD 模板可复用，但 sys_user 复杂 JOIN 需 AI 多轮调整 |
| Service / ServiceImpl | 95% | 业务规则由 PRD 直接转化，AI 一次命中率高 |
| Controller | 96% | @PreAuthorize + 路径参数，模板化高 |
| Vue 页面（view） | 88% | 表格/表单 UI 由 AI 一次性产出，但**样式/响应式**常需多轮调整 |
| Pinia store / API 封装 | 97% | 几乎纯模板 |
| SQL DDL（schema-rebuild.sql） | 70% | 用户主导设计（MySQL 工作台），AI 辅助生成 INSERT 语句 |
| SQL DML（数据迁移） | 50% | sys_dept 中文数据由用户手填（双重编码问题由用户 Workbench 修） |

## 7. 关键发现与洞察
### 7.1 AI 协作的高价值场景（命中率高）

1. **后端 CRUD 模板代码**：Controller + Service + Mapper 三层结构化代码，AI 一次命中率 96%
2. **数据库 DDL 与种子数据**：标准表结构 + 标准化 INSERT 语句
3. **测试用例编写**：基于 PRD 步骤直接转化为 Gherkin-like 用例
4. **文档格式化与回填**：会议记录/日志/缺陷表等结构化文档
### 7.2 AI 协作的低价值场景（需多轮调整）

1. **跨模块架构决策**（如 permVersion）：单次对话难以收敛
2. **环境/工具链配置**（如 jdbc URL、双实例）：依赖运行时反馈才能确诊
3. **业务规则边界**（如 UC-016 月份参数）：PRD 表述模糊时需多轮澄清
4. **前端交互细节**（如级联、复杂表单校验）：UI 体验调整主观性强
### 7.3 人机协作关键经验

1. **AI 一次命中率与 PRD 详尽度正相关**：PRD 越清晰（字段、规则、异常流），AI 一次命中率越高
2. **缺陷修复轮次与缺陷等级反相关**：P0 反而一次闭环率高（因为 P0 阻塞紧急，重试积极）
3. **人工介入点集中在三处**：
   - 环境配置歧义（jdbc URL、端口冲突）
   - 权限/角色绑定（需结合 Workbench 实际数据）
   - 偏差决策（哪些"实现选择"该保留/修复）
4. **文档编写是 AI 协作的最大提速场景**：8,886 行文档从传统 ~360 小时压缩到 14 小时（25.7×）
### 7.4 改进建议

| 改进项 | 目标 | 建议措施 |
|--------|------|----------|
| 降低 P1 持续项比例 | DEF-011 类持续项 ≤ 5% | 架构债务尽早识别并排期，避免堆积 |
| 提升 SQL 一次命中率 | 90% → 95% | 在 Mapper 接口注释明确字段别名约定 |
| 减少前端交互轮次 | 平均 1.5 轮 → 1.2 轮 | 在 UI 设计阶段固化组件库选型（element-plus 已选） |
| 文档编写提速 | 25.7× → 30× | 建立"会议纪要 → 日志"自动化模板 |
