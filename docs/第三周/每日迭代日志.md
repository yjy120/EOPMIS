## 3. AI 协作问题与解决
### 3.1 工具调用层面的问题

| 问题 | 表现 | 解决策略 |
|------|------|----------|
| **PowerShell 解析限制** | `&>` 重定向 / here-string 头后跟字符 / `$global:LASTEXITID or $PID` 都被 PS5 拒绝 | 改用 `Start-Process ... -RedirectStandardOutput/Error -WindowStyle Hidden` |
| **`mvn -D` 参数解析失败** | `Unknown lifecycle phase ".run.profiles=dev"` | 改用 `SPRING_PROFILES_ACTIVE=dev` 环境变量 |
| **PowerShell 把 `127.0.0.1` 截断** | `Unknown MySQL server host '127'` | 加双引号 `"127.0.0.1"` |
| **JDK 版本不兼容** | JDK 21/26 与 Spring Boot 2.7 编译失败 | 切到 `C:\Program Files\Microsoft\jdk-17.0.20.101-hotspot\` |
| **后台进程相互干扰** | 重启后端时出现两个 java 进程（PID 20216 + 26044） | 先 `Get-NetTCPConnection -LocalPort 8080` 找占用者再 Stop-Process |
| **PowerShell 输出编码** | API 返回的 UTF-8 字节被 PowerShell 按 GBK 解码，导致控制台看像"乱码" | 用 `curl.exe` 写文件 + `Get-Content -Encoding UTF8` |
### 3.2 业务/技术层面的问题

| 问题 | 表现 | 解决策略 |
|------|------|----------|
| **MySQL 服务端默认 latin1** | my.ini 第 101 行 `# character-set-server=` 被注释 | **不能**通过 `net stop/start MySQL80` 重启服务（Access denied），改为应用层强制 SET NAMES |
| **Druid `connection-init-sqls` 字符串形式无效** | YAML 字符串在 Spring Boot 解析时被忽略 | 改用 list 形式 + `@PostConstruct` 主动调用 `setConnectionInitSqls` + 跑一次 SET NAMES 验证 |
| **JDBC URL `sessionVariables` 不生效** | 新增 sys_position 数据被替换为 `?` | 同上，应用层强制覆盖 |
| **sys_dept 双重 UTF-8 编码** | 数据是"总公司"UTF-8 字节被双重 latin1 转换（`C3A6 E282AC C2BB...`） | 用 `CONVERT(BINARY CONVERT(field USING latin1) USING utf8mb4)` 反向解码 |
| **el-tree-select 默认折叠** | 下拉里只显示根节点"总公司" | 加 `default-expand-all` 属性 |
### 3.3 用户沟通层面的问题
| 问题 | 表现 | 应对策略 |
|------|------|----------|
| **用户描述模糊带情绪** | "页面什么都没有，点不进去"（实为乱码） | 不要急于"修空白"，先用浏览器实测 + DB hex 验证是否为字符集问题 |

| **双重编码继续发生** | sys_menu / sys_employee 的种子数据再次出现双重编码（导入时 latin1 默认） | 沿用 `CONVERT(BINARY CONVERT(...))` 反向解码 |

## 3. AI 协作问题与解决
### 3.1 工具调用层面的问题

| 问题 | 表现 | 解决策略 |
|------|------|----------|
| **双 MySQL 实例并存** | 3306 同时被 MariaDB(IPv4) + MySQL 8.0(IPv6) 监听，backend 连 IPv4 命中 MariaDB | `Get-NetTCPConnection -State Listen` 列出 LocalAddress/OwningProcess；按 ListeningProcess 找 PID → 查 ExecutablePath 确认实例；最后强制走 IPv6 |
| **PowerShell `[System.IO.File]::ReadAllBytes` 在 sandbox 返回 null** | 直接读 dump 文件失败 | 改用 `mysql.exe -e "SOURCE C:/Users/.../file.sql"`（路径用 `/` 代替 `\`） |
| **PowerShell 写 SQL 中文乱码** | sandbox 把 `.sql` 文件按 GBK 重编码保存，导致中文双重编码 | 改用 mysql 客户端内置 `--default-character-set=utf8mb4` + SOURCE 命令直接喂入 |
| **`mysqldump` latin1 默认** | 导出 MariaDB 数据时 UTF-8 字节被 latin1 错读 | 显式 `--default-character-set=utf8mb4` |
| **`mysql.exe -e "SOURCE <file>"` 路径反斜杠** | `\` 在 mysql 客户端内部被解释为命令 | 路径中用 `/` 代替 |
| **`npm.cmd` 找不到 `node`** | PowerShell PATH 缺 `C:\Program Files\nodejs` | `$env:Path = "C:\Program Files\nodejs;$env:Path"` 前置注入 |
| **mvn 占用导致 jar 打包失败** | 后端进程在跑，target 文件被锁 | `Get-Process -Name java \| Stop-Process -Force` 再 mvn package |
### 3.2 业务/技术层面的问题

| 问题 | 表现 | 解决策略 |
|------|------|----------|
| **MySQL 客户端解析 localhost 行为差异** | `mysql.exe -h localhost` 命中 MySQL 8.0；Java JDBC `localhost` 命中 MariaDB | Java 端 jdbc URL 用 `[::1]` 强制 IPv6；mysql.exe 默认走 IPv6 优先 |
| **sys_salary Wrapper 别名 s.** | MyBatis-Plus `qw.eq("s.employee_id", ...)` / `orderByDesc("s.salary_month")` 表无别名 s → `Unknown column 's.salary_month'` | 去掉 `s.` 前缀，让 Wrapper 直接拼到主表 sys_salary |
| **sys_dept 双重编码历史数据** | MariaDB 早期 latin1 写入 + UTF-8 叠加，原值无法 `CONVERT` 反向解码 | 直接 DELETE + INSERT 7 条正确中文，保留所有外键引用 |
| **MariaDB → MySQL 8.0 跨实例字符集陷阱** | 客户端 latin1 连接 → 导出 UTF-8 字节被错读为 latin1 → 导入到 MySQL 8.0 仍乱码 | dump 用 utf8mb4 + 导入 `SET NAMES utf8mb4` + 双重编码数据直接重写 |
| **菜单 ID 已被占用** | 4001-4004 已被 employee 按钮占用 → `Duplicate entry '4001'` | 改用 4101-4104 系列（避开 employee 已用段） |
| **DataInitRunner 初始化遗漏 HR 个人中心权限** | HR(2) 缺 me:pwd:update / me:profile:view 绑定 | INSERT IGNORE 显式补绑定（沿用 I-8 经验） |
| **MenuMapper/Role 边界持续遗漏** | 每个新迭代都会过一遍 admin/HR/EMP 菜单边界 | 沿用 I-8 三层校验：1) DataInitRunner SQL 2) sys_role_menu 实际绑定 3) Layout.vue 精确 perm |
### 3.3 用户沟通层面的问题

| 问题 | 表现 | 应对策略 |
|------|------|----------|
| **用户连续抱怨"又没了""又不见了"** | 表达情绪化，实际是双实例切换导致旧数据"看不见" | 启动 AdvisorTool 请求策略指导（双实例对齐 + 数据回填顺序） |
| **用户对诊断结果反复质疑** | "你再修改一下" / "不是，你真确定改了吗" | 用 API 返回 perms 数组 + DB SELECT 双重证据证明已生效，主动提议 `localStorage.clear()` |
| **用户要求"数据都没有，你自己写"** | 演示数据为空影响体验 | 接受请求，按"补依赖 → 业务主表 → 跨实例迁移 → API 验证"分步执行；明确告知是 demo 数据 |

## 4. 提示词策略调整
### 4.1 已调整的策略

| 调整点 | 调整前 | 调整后 | 触发条件 |
|--------|--------|--------|----------|
| **jdbc URL 优先级** | `127.0.0.1` 直连 IPv4 | `[::1]` 强制 IPv6（前提：确认 3306 上有 IPv6 listener 的 MySQL 实例） | 检测到 3306 多实例并发时 |
| **MySQL 双实例快速鉴别** | 假定 3306 = MySQL | `Get-NetTCPConnection -State Listen` 列出 ListeningProcess → `Get-CimInstance Win32_Process` 看 ExecutablePath + Version | 任何 backend 连不上预期表时 |
| **mysqldump 跨实例字符集** | 默认 latin1 | 显式 `--default-character-set=utf8mb4` | 任何 MariaDB → MySQL 数据迁移 |
| **mysql 跨实例导入路径分隔符** | `\` 反斜杠被 mysql 客户端解释为命令 | 路径用 `/` 正斜杠 | `mysql -e "SOURCE ..."` 命令 |
| **sandbox 写文件编码陷阱** | 默认信任 Write 工具 UTF-8 | 显式用 mysql 客户端 `SOURCE` 命令直接喂入，不经磁盘中转 | 涉及中文 INSERT |
| **sys_dept 双重编码数据** | 尝试 `CONVERT` 反向解码 | 直接重写（CONVERT 不一定成功） | 历史脏数据场景 |
| **DataInitRunner 完整性预检** | 启动时不校验 | 每个新迭代主动 SELECT sys_role_menu 比对预期矩阵 | 任何修改 sys_role_menu 的迭代 |
| **重启策略** | 默认重启 backend | 优先检查 `Get-Process -Name java` 是否在跑 + 用户报告问题是否真的需要重启 | 用户问"要不要重启系统" |
