## 一、系统总体架构概述

### 1.1 系统定位

本系统为单组织企业内部使用的 B/S 架构人事管理信息系统，服务系统管理员、人事专员、普通职工三类角色，覆盖"组织管理 → 人员建档 → 合同签订 → 岗位调动 → 薪资考勤"业务主线，支撑 1000 名以内职工规模的数据存储与查询，部署于企业内网（远程访问走 VPN）。

### 1.2 总体技术架构

系统采用**前后端分离的经典分层单体架构**（不引入微服务），技术选型与 PRD、技术路线评估结论保持一致：

| 组成部分 | 技术选型 | 说明 |
|----------|----------|------|
| 客户端 | Chrome / Edge / Firefox 浏览器 | 不支持 IE；前端 SPA 页面 |
| 前端 | Vue 3 + Element Plus + Vue Router + Pinia + Axios | 页面、路由、状态管理、接口请求封装 |
| 接入/代理 | Nginx 1.20+ | 静态资源托管、反向代理、负载入口（单节点即可起步） |
| 后端框架 | Spring Boot 2.7.x（JDK 11） | 【已评审】2.7 |
| Web 层 | Spring MVC | RESTful 接口、参数校验、统一返回 |
| 安全框架 | Spring Security + JWT（或 Session） | 认证、RBAC 鉴权、接口级权限；令牌方式 |
| ORM | MyBatis + MyBatis-Plus | Mapper 接口 + XML/注解 SQL，分页插件 |
| 连接池 | Druid 1.2+ | 连接池、SQL 监控 |
| 数据库 | MySQL 8.0 | InnoDB、utf8mb4 |
| 构建/部署 | Maven、内嵌 Tomcat、jar 包运行 | Nginx 反代至 Spring Boot 服务端口 |
| 附件存储 | 服务器本地文件目录（合同附件等） | 本地目录 |

总体物理形态（逻辑视图）：

```
浏览器(三类角色) ──HTTP/HTTPS──> Nginx(静态页面+反向代理)
                                      │ /api/**
                                      v
                          Spring Boot 应用(内嵌Tomcat,单进程)
                          ┌────────────────────────────┐
                          │ Controller / Service /     │
                          │ Mapper / Security / AOP    │
                          └────────────────────────────┘
                                      │ JDBC(Druid)
                                      v
                                  MySQL 8.0
                          附件文件 ──> 服务器约定目录
```

### 1.3 架构设计思路

1. **分层架构、单向依赖**：严格按"接入层 → 控制层 → 业务逻辑层 → 数据访问层 → 数据库层"五层组织代码，上层依赖下层，禁止跨层调用与逆向依赖。
2. **前后端分离、接口契约化**：Vue 只负责展示与交互，后端只提供无状态（或会话态）RESTful JSON 接口；前端菜单裁剪只做体验优化，一切权限以后端校验为准。
3. **按业务领域模块化拆包**：后端包结构按账号、员工、部门、岗位、档案、请假、权限七个业务模块组织，模块之间只通过 Service 接口发生调用，避免模块内部类互相穿透。
4. **安全能力横切内建**：针对 PRD 提出的核心复杂工程问题（细粒度权限 + 字段级脱敏 + 全链路留痕），将认证鉴权（Filter）、数据权限拦截（MyBatis 插件/查询条件）、脱敏（序列化注解）、审计日志（AOP）设计为横切组件，而非散落在业务代码中。
5. **数据权限下沉**：普通职工"本人数据"过滤在数据访问层统一追加查询条件，业务层不得靠手工传参控制，防止篡改参数越权。
6. **事务边界落在业务层**：调动生效、薪资发放、请假联动考勤等跨表操作在 Service 层以声明式事务保证一致性。
7. **统一规约**：统一返回体、统一异常处理（@RestControllerAdvice）、统一参数校验（JSR-303）、统一分页格式、配置外置（application.yml，多环境 profile）。
8. **可扩展预留**：角色、权限、字典采用表驱动而非硬编码；业务模块可独立增加；单体内部按模块边界收敛，为将来拆分预留可能（本版不做微服务）。

## 二、系统完整分层架构设计

### 2.1 五层总览

| 层级 | 名称 | 主要载体 | 核心产物 |
|------|------|----------|----------|
| 第一层 | 接入层 | 浏览器、Nginx、Vue3 静态资源 | 页面展示、请求入口、反向代理 |
| 第二层 | 控制层 | Spring MVC Controller | REST API、参数校验、认证入口、结果封装 |
| 第三层 | 业务逻辑层 | Service / 领域组件 | 业务规则、事务、权限/脱敏/审计编排 |
| 第四层 | 数据访问层 | MyBatis Mapper、数据权限组件 | CRUD、SQL、行级权限、加解密 |
| 第五层 | 数据库层 | MySQL 8.0、附件目录、日志存储 | 业务数据、索引、备份恢复 |

横切于第二、三、四层之上的公共组件：Spring Security 过滤链、AOP（审计日志、数据权限、字段脱敏）、全局异常处理器、统一日志（DEBUG/INFO/WARN/ERROR）。

### 2.2 第一层：接入层

**作用**：系统对用户的唯一入口，负责把用户操作转化为 HTTP 请求，并承载静态资源与请求转发。

**职责**：

1. 提供浏览器可访问的 Web 页面（登录页、各业务列表/表单页、个人中心）。
2. Nginx 托管 Vue 打包后的静态资源（HTML/JS/CSS/图片）。
3. Nginx 将 `/api/**` 请求反向代理到 Spring Boot 服务，规避浏览器跨域问题（或由后端 CORS 配合）。
4. 前端路由守卫做菜单/按钮级可见性控制（仅体验优化，非安全边界）。
5. Axios 拦截器统一携带认证令牌（JWT/Session Cookie）、统一处理 401/403/业务错误码。
6. 【待评审】HTTPS 终止、内网访问控制、VPN 接入策略在部署设计中细化。

**包含内容**：

- 前端工程 `frontend/`：`views/`（页面）、`components/`（公共组件）、`router/`（路由与守卫）、`store/`（Pinia 状态）、`api/`（接口封装）、`utils/`。
- Nginx 配置：静态根目录、`/api` 代理规则、gzip、上传大小限制。
- 文件上传/下载入口（合同附件）。

**层级关系**：接入层只与控制层通信，不直接访问业务层、数据层和数据库。

**数据流转方向**：用户操作 → 前端组装请求（JSON/表单）→ Nginx → 控制层；响应原路返回，前端渲染。

### 2.3 第二层：控制层

**作用**：接收并分发请求，是后端 API 的边界层，负责"协议级"工作，不写业务规则。

**职责**：

1. 以 RESTful Controller 暴露各模块接口（如 `EmployeeController`、`LeaveController`）。
2. 接收并完成**入参校验**（`@Valid` + JSR-303：非空、长度、手机号/身份证格式、日期区间、金额非负等）。
3. 作为认证鉴权拦截点：未登录请求由 Security 过滤链拦截（401）；接口级权限由 `@PreAuthorize` 等注解校验（403）。
4. VO/DTO 与 Entity 隔离：控制层出入参使用 DTO/VO，禁止把数据库实体直接暴露给前端。
5. 调用对应模块的 Service 接口完成业务，按统一返回体（code/message/data）封装结果。
6. 抛给全局异常处理器统一处理业务异常、参数异常、权限异常、系统异常。
7. 文件上传/下载接口的入口控制（类型、大小校验）。

**包含内容**：`controller/` 包（7 个模块各一组 Controller）、`dto/`、`vo/`（或并入 dto）、`config/`（Web/Security/CORS 配置）、`exception/`（全局异常处理）。

**层级关系**：向下只调用业务逻辑层 Service 接口；不直接调用 Mapper；不处理跨模块业务编排以外的逻辑。

**数据流转方向**：接入层请求 → 反序列化为 DTO → 校验 → 调用 Service；Service 结果 → 封装统一返回体 → JSON 回到接入层。

### 2.4 第三层：业务逻辑层

**作用**：系统核心，承载所有业务规则、事务边界与跨模块编排，是事务与安全策略的主要落地点。

**职责**：

1. 实现各模块业务逻辑：唯一性校验、状态机（合同状态、请假单状态、账号状态）、到期预警计算、删除前置约束等。
2. **声明式事务管理**：人事调动生效（写调动记录 + 更新员工部门岗位）、薪资发放锁定、请假审批通过写考勤等跨表操作必须在同一事务内，失败整体回滚。
3. 组织模块间调用：如调动 Service 调用员工 Service 更新主数据；请假审批通过后调用考勤/档案域写记录。
4. 承载"功能权限"上下文判断（当前用户角色是否允许操作本类业务）；**行级"本人数据"权限由数据访问层配合执行**。
5. 通过 AOP/注解输出操作审计日志（谁、何时、对哪条记录、做了什么、是否成功）。
6. 敏感字段**脱敏编排**：HR 业务操作上下文取完整数据，普通职工查询上下文取脱敏数据（身份证号、银行账号、薪资等）。
7. 密码加密（BCrypt）、登录失败计数/锁定、会话失效等安全业务逻辑。
8. 处理业务异常并转换为明确的业务错误码与提示语。

**包含内容**：

- `service/` 与 `service/impl/`：七个模块各一组 Service 接口与实现。
- 领域组件/策略：状态计算器（合同 30 天到期标识）、脱敏策略、权限注解处理、审计切面（`aspect/`）。
- `util/`：密码、日期、编号生成等工具。

**层级关系**：向上被控制层调用；向下通过 Mapper 接口访问数据；同层模块间仅通过对方 Service 接口调用，禁止直接操作对方 Mapper。

**数据流转方向**：接收 DTO/参数 → 业务校验与处理 → 组装查询条件或实体 → 调 Mapper；拿到 Entity/结果 → 加工（脱敏、组装 VO）→ 返回控制层。

### 2.5 第四层：数据访问层

**作用**：隔离业务逻辑与数据库细节，负责一切持久化操作，是行级数据权限与存储安全的最后一道闸口。

**职责**：

1. 基于 MyBatis Mapper 接口 + XML 实现各表 CRUD 与多条件组合查询、分页查询。
2. 借助 MyBatis-Plus 分页插件统一分页（默认每页 20 条）。
3. **行级数据权限**：对普通职工的档案/合同/薪资/考勤/请假查询，由数据权限拦截器或统一查询条件自动追加"职工ID = 当前登录人绑定职工ID"，业务代码无法绕过。
4. **字段加解密**：身份证号、银行账号等落库加密字段通过 TypeHandler 或专用列处理完成写入加密、读取解密；密文不对业务层以外暴露。
5. 乐观锁/版本控制：薪资发放确认、合同续签等并发更新场景防止重复提交。
6. 批量操作支持（考勤批量录入）。
7. 绝不拼接裸 SQL，全部使用预编译参数，防 SQL 注入。

**包含内容**：`mapper/` 包（每模块一组 Mapper）、`resources/mapper/*.xml`、数据权限拦截器、加解密 TypeHandler、基础 Entity 与分页对象。

**层级关系**：向上仅被业务层调用；向下持有数据库连接（Druid）访问 MySQL；不包含任何业务判断与界面概念。

**数据流转方向**：接收实体/查询参数 → 生成并执行 SQL → 返回 Entity 或统计结果；写入时完成加密，读取时完成解密。

### 2.6 第五层：数据库层

**作用**：系统数据的最终承载与持久化保障。

**职责**：

1. 存储全部业务数据：账号、角色、权限、员工、部门、岗位、档案明细、合同、调动、薪资、考勤、请假单、操作日志、字典等表（表清单在概要设计/详细设计阶段给出 ER 图）。
2. 通过主键、唯一约束（登录账号、职工编号、身份证号、合同编号、职工+薪资月份、职工+考勤日期）、非空约束、外键或逻辑外键保证数据完整性。
3. 在职工编号、身份证号、合同编号、常用查询列（部门、岗位、月份、日期）上建立索引保障列表性能。
4. 附件文件存储于约定目录、数据库仅存路径与元数据。
5. 定期自动备份（mysqldump/计划任务）与恢复演练；业务用户无权修改/删除审计日志。
6. 字符集 utf8mb4，存储引擎 InnoDB（支持事务）。

**包含内容**：MySQL 8.0 实例与库表、初始化脚本、索引、备份文件、附件目录、审计数据。

**层级关系**：只与数据访问层交互（JDBC），不感知上层业务与页面。

**数据流转方向**：接收 Mapper 的 SQL 执行读写；结果集回传数据访问层。

### 2.7 层级关系与数据流转总结

**依赖方向（编译期，单向）**：

```
接入层 → 控制层 → 业务逻辑层 → 数据访问层 → 数据库层
        （上层依赖下层，禁止逆向、禁止跨层；同层模块间仅经 Service 接口调用）
```

**一次完整请求的运行期流转（以"普通职工查询本人薪资"为例）**：

```
下行：浏览器 → Nginx → Security认证/鉴权 → Controller参数校验
      → SalaryService（判断角色上下文、开启只读事务）
      → SalaryMapper（数据权限组件自动追加 employee_id = 当前用户绑定职工）
      → MySQL 执行查询
上行：MySQL结果集 → Mapper映射为实体（加密字段解密）
      → Service按角色脱敏（本人查本人薪资可全显/部分显，规则待评审）
      → Controller封装统一返回体 → Nginx → 浏览器渲染
异常：任一层异常 → 全局异常处理器 → 标准错误码/提示 → 前端展示；ERROR级日志落盘
审计：Service方法命中审计切面 → 异步/同步写入操作日志（本次为"查看"敏感信息，按PRD需留痕）
```

## 三、系统整体模块划分

### 3.1 划分原则
1. 按 PRD 业务领域划分，模块高内聚、低耦合；每个模块在后端对应独立的 Controller/Service/Mapper/Entity 一组类，前端对应一组页面与 api 文件。
2. 本次初稿按任务要求划分为 **7 个业务模块**；另设**公共支撑组件**（认证、审计、字典、通知）横切服务于所有模块。
3. 模块内再分子功能；模块间调用只允许走 Service 接口。

> **【评审修订 2026-09-10】** 原 7 模块方案在评审后调整为 **10 个业务模块**（M01~M10）。原因：原 M05 聚合了档案/合同/调动/薪资/考勤 5 类业务，模块过重、与 PRD 一一对应原则不符；现将合同、调动、薪资、考勤各自升级为顶层模块，原档案子表并入 M02，详见 §3.2 与 §4。

## 四、各模块详细功能职责

> 每个模块给出：模块职责、子功能清单、后端类初拟、关键业务规则。类名为初稿建议，概要设计阶段可调整。

### 4.1 M01 用户账号模块

**模块职责**：负责系统登录认证、会话与账号生命周期管理；不负责角色权限定义（归 M10），但负责为账号分配既有角色。

**子功能**：

| 子功能编号 | 子功能 | 说明 |
|-----------|--------|------|
| M01-01 | 登录认证 | 账号+密码校验；BCrypt 比对；校验账号状态；成功后创建会话/签发 JWT 并按角色跳转首页 |
| M01-02 | 登录失败处理 | 错误统一提示"账号或密码错误"；连续错误 5 次锁定账号 15 分钟；停用账号拒绝登录 |
| M01-03 | 退出登录 | 注销会话/令牌失效；记录登出日志 |
| M01-04 | 会话管理 | 闲置 30 分钟自动失效；前端拦截 401 跳登录页 |

### 5.2 依赖规则（架构约束）

1. 上层（Controller）只能调本模块 Service；跨模块业务一律调对方 **Service 接口**，禁止跨模块直接注入 Mapper。
2. M03、M04、M10 为底层被依赖模块，不反向依赖业务模块。
3. M10 作为横切底座以框架机制（Security/AOP/拦截器）作用于各模块，业务代码不反向实现权限逻辑。
4. 禁止循环依赖：M02 不得反向调用 M05~M09 各业务模块；员工离职的占用校验由 M02 发起查询对方 Service 是否存在关联数据。
5. 数据库表之间允许逻辑外键关联；使用物理外键【已评审】，建议关键字段加唯一索引、由应用层保证引用完整性。

### 5.3 典型调用链（文字时序）

**调用链 1：登录**

```
前端登录页 → AuthController.login
  → LoginService：查账号 → BCrypt 校验 → 判断锁定/停用
  → 调 M10 加载角色权限 → 签发令牌/建会话
  → AuditLogService 记登录日志 → 返回首页路由信息
```

**调用链 2：人事调动生效（事务）**

```
TransferController.apply
  → TransferService（@Transactional 开启事务）
    → DepartmentService/PositionService 校验目标有效
    → TransferMapper 保存调动记录（状态=已生效）
    → EmployeeService.updateDeptPosition 回写员工主数据
    → AuditLogAspect 记录变更
  → 任一步失败整体回滚 → 全局异常返回提示
```

**调用链 3：普通职工查本人薪资（权限+脱敏+审计）**

```
SalaryController.myList → Security 校验登录与角色
  → SalaryService.queryMine
    → SalaryMapper（数据权限拦截器自动加 employee_id=本人）
    → 结果经脱敏序列化 → AuditLog 记录"查看薪资"行为
  → 统一返回体回前端
```

**调用链 4：请假审批通过（若 M09 立项）**

```
LeaveController.approve → LeaveService（@Transactional）
  → 校验状态=待审批、操作人有审批权限
  → 更新请假单=已通过（记录意见/时间/人）
  → AttendanceService.saveOrUpdateLeaveRecord 写考勤
  → 审计留痕 → 返回结果
```
