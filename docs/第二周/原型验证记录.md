## 3. 缺陷登记

### B-1【P1】首次初始密码未写入历史表，导致"改密回原密码"无校验

- **关联用例**：T2.5
- **复现步骤**：
  1. 以 `smoke01 / Init@123` 登录（密码由管理员 `initialPassword` 字段创建）
  2. 调用 `POST /api/auth/changePassword`，body = `{"oldPassword":"Init@123","newPassword":"Init@123","confirmPassword":"Init@123"}`
  3. 预期：返回 40013 "新密码不能与最近 3 次使用过的密码相同"
  4. 实际：返回 `{code:0, message:"ok"}` —— 改密成功
- **根因**：
  - [UserAdminServiceImpl](file:///c:/Users/Lenovo/Desktop/EOPMIS/backend/src/main/java/com/eopmis/service/impl/UserAdminServiceImpl.java) 创建账号时只 `BCrypt` 了 `initialPassword` 写入 `sys_user.password`，**没有同时写 `sys_password_history`**
  - [AuthServiceImpl#changePassword](file:///c:/Users/Lenovo/Desktop/EOPMIS/backend/src/main/java/com/eopmis/service/impl/AuthServiceImpl.java#L168-L173) 的历史检查 `selectRecentByUserId` 返回空 → 循环不进 → 直接放行
- **风险**：
  - 用户可绕过"近 3 次不可复用"的策略；
  - 与 [概要设计说明书 4.3 密码策略] 冲突；
  - 测试方案与用例集 TC-PWD-04 / TC-PWD-05 不通过。
- **修复建议**（任选其一）：
  1. 在创建账号成功后**同步**插入一条 `sys_password_history` 记录（推荐）；
  2. 在改密时**额外**比较"当前 `sys_user.password`"作为历史第 0 条；
  3. 改密主成功场景时判断"新旧密码相同"直接拒绝。
- **责任方**：后端主程
- **目标版本**：第一个 HR 业务模块 PR 前

### B-2【P2 / 业务保护，非缺陷】HR 角色仍被用户引用时拒绝修改权限

- **关联用例**：T4.3
- **现象**：调用 `POST /api/admin/role/assign` 给 HR 角色（id=2）分配菜单 `[21, 22]`，返回 `{code:40032, message:"该角色仍被用户使用，请先调整用户角色"}`。
- **判定**：**这是业务保护逻辑，非缺陷**。
  - 防止运营误操作：HR 角色被 hr01 引用，若中途给 HR 角色减权限会导致 hr01 业务中断。
  - 但当前实现一刀切："任何引用都不让改"，不够友好。
- **建议优化**：
  - 拆成两个接口：`PATCH /admin/role/{id}/menus`（加权限）和 `DELETE /admin/role/{id}/menus/{menuId}`（减权限），并对"减权限"加保护；
  - 或在响应中加字段 `affectedUsers: [hr01]`，让管理员先调整用户。
- **优先级**：P2，与第一个 HR 业务模块 PR 同步整改。
